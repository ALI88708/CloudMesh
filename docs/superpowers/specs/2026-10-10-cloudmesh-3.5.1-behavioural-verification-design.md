support for all commands that should work, an improved project website, and a CI

## Sub-project A â€” Behavioural CLI harness

### The problem this solves

`smoke_cli.py` now walks all 286 command paths and asserts each answers
`--help`. That catches a broken import chain and a missing package. It cannot
tell you whether `cm panic` rotates a key, whether `cm group add` persists a
group, or whether `cm transfer` copies a file. Three bugs fixed in the last week
â€” the drifting aliases, the flat `Copy-Item` payload, the documented commands
that never existed â€” would all have passed.

### The isolation constraint, found by inspection

`StorageManager.__init__` defaults `base_dir` to `Path(__file__).parent.parent`,
the directory containing the installed package:

    db_path  = <package>/cloudmesh.db
    key_path = <package>/.secret.key

There is no environment override. So on a developer's machine every
storage-touching command writes to the real package directory â€” the worktree
carries a 118 KB `cloudmesh.db` and a `.secret.key` from earlier runs â€” and
**one** test in 330 isolates `HOME` or `USERPROFILE`. Naively executing all 286
commands would have `cm panic` rotate the real key and `cm uninstall` delete the
real install. That, not an oversight, is why `SAFE_COMMANDS` holds only 80
entries.

### `CLOUDMESH_DIR`: a documented, user-facing setting

Decision: the override is a **supported, documented feature** for both users and
tests. It is not a test-only hook.

`StorageManager.__init__` reads the environment before falling back to the
package directory:

    base_dir = Path(os.environ.get("CLOUDMESH_DIR") or Path(__file__).parent.parent)

Because the behaviour is user-facing, it ships with the full treatment rather
than as a one-line change:

- **A `doctor` row** showing the active base directory, so a user who has set it
  can confirm it took effect. This matters because a wrong `CLOUDMESH_DIR`
  silently relocates their database and keys, and without a row they would have
  no way to notice.
- **A README section** explaining the setting, its default, and the isolation use
  case.
- **A CONTRIBUTING.md note** for contributors writing tests, so the harness's
  approach is discoverable rather than folklore.
- **Tests for the override itself**: honours the variable, ignores it when unset,
  rejects a path it cannot create, and leaves the package directory untouched.

Rejected alternatives: copying the package tree per test (fights `sys.modules`
caching, makes coverage attribution ambiguous) and dependency-injecting a
`StorageManager` into every handler (large diff, and it does not help the
subprocess tests that give this harness its value).

### Two layers, deliberately unequal

Writing 286 hand-authored effect assertions is months of work and would rot.

**Layer 1 â€” universal, cheap, generated.** All 286 paths run isolated and assert:

- exit code is in a sane set, not a traceback exit
- no `Traceback` on stdout or stderr
- the isolated `HOME`, `USERPROFILE`, and `CLOUDMESH_DIR` were the only trees
  written

That last assertion earns its keep: it turns "this command wrote somewhere
unexpected" from an invisible surprise into a failure.

**Layer 2 â€” deep effect assertions, size derived rather than chosen.**

The review decision is that the depth of Layer 2 is **not a fixed number**. It is
derived from the risk each command actually carries, using two measurable
properties:

1. **Lines of the handler's implementation.** A 200-line handler has more
   branches, and therefore more ways to be wrong, than a 6-line wrapper. The
   number of paths through it scales with the code.
2. **Complexity per PR.** As pull requests grow more complex, the commands they
   touch get deeper coverage, because that is where regression risk concentrates.

Concretely, the manifest records `handler_lines` per command, and the harness
reports the **coverage ratio** â€” deep-tested commands Ã· total commands â€” rather
than an absolute count. The ratio is what CI enforces as a floor, so the target
moves as the codebase does instead of going stale. Each destructive or
key-rotating command is required to have a deep assertion regardless of size;
size only decides how far beyond that the coverage reaches.

This also gives a real answer to "how many is enough": enough that the ratio
covers every high-risk command and tracks handler size for the rest.

### Where the manifest lives

A single declarative table, one entry per path:

    ("panic", ),
        safety        = DESTRUCTIVE,
        handler_lines = 184,
        fixture       = isolated_home,
        asserts       = [key_rotated, old_key_rejected],

| Class | Meaning | Handling |
| --- | --- | --- |
| `SAFE` | Read-only or trivially reversible | Run directly |
| `ISOLATED` | Writes state | Temp `HOME`, `USERPROFILE`, `CLOUDMESH_DIR` |
| `DESTRUCTIVE` | Deletes, rotates keys, overwrites | Isolated **and** effect-asserted, so a missing guard is itself a failure |
| `NETWORK` | Needs a reachable SSH host | Skipped, with a stated reason |

No entry may be `NETWORK` by convenience. Each needs a comment saying why it
cannot be tested, and the count is reported in the test output so the gap is
visible and shrinkable rather than permanently hidden.

### Files

- `cloudmesh/tests/command_manifest.py` â€” declarative table and safety enum. Data
  only, no logic.
- `cloudmesh/tests/behaviour_harness.py` â€” the runner. Builds the isolated

### What this deliberately does not do

- Node-agent commands needing a live agent stay `NETWORK` with a stated reason.
- The existing 330 tests are added to, not reorganised. Several textual
  assertions (LF endings, executable bit, the `Copy-Item` destination) are the
  right tool for a static file contract and stay.

## Sub-project C â€” Property-based testing

Hypothesis, where the input space is too large for hand-written examples:

- Configuration key parsing: any string, any casing, any separator.
- Path handling on both platforms: separators, `..`, absolute vs relative, and
  reserved Windows device names (`CON`, `NUL`, `PRN`).
- **Arg parsing: no argument vector may produce an uncaught traceback.** This is
  the highest-value target and connects directly to goal two, because it
  subsumes much of the value of fuzzing the CLI.

### Depth

- **Command reference verified against the parser.** The site states commands; it
  gains the same guarantee `CONTRIBUTING.md` now has. A test extracts every
  documented invocation from `site/index.html` and checks it against the real
  parser, so the site cannot reintroduce the documented-but-nonexistent commands
  that shipped for months. This is the one piece of E that is a correctness fix
  rather than polish.
- **Release notes from the live API**, already wired; add the changelog content
  for 3.5.1 and surface what changed rather than only what shipped.
- **Per-command detail.** The 286 verified paths are grouped by area (servers,
  nodes, files, security, monitoring) so the reference is navigable rather than
  one long list.
- **Correct 3.5.1 facts** in the hero facts and copy.

### Motion

Scoped to motion that carries meaning, not decoration for its own sake:

- **Scroll-triggered reveals.** Sections fade and rise into place once as they
  enter the viewport. Built on `IntersectionObserver` rather than scroll
  listeners, so it does not run a handler per frame.
- **Hero entrance.** A short staggered entrance for the hero copy and actions.
- **Hover and focus feedback** on the cards and links that already have
  transitions, made consistent and slightly richer.
- **Reduced motion is a hard requirement, not an afterthought.** The existing
  `@media (prefers-reduced-motion: reduce)` block already neutralises animations
  and transitions globally. New motion must be written so that block keeps
  working â€” that means no animation whose *end state* depends on the animation
  running, because then a reduced-motion user would get content stuck at
  `opacity: 0`. Reveals therefore set the resting state as the default and use
  the animation only to *transition into* it.

### Accessibility constraints

The site already has a `skip-link`, `aria-label`s, semantic sections, and the
reduced-motion block. New work must not regress these, and:

- reveals must never be the only thing making content visible
- focus order must stay correct after content is inserted
- `prefers-reduced-motion` must continue to neutralise everything new
- contrast must be checked for any new colour used

### Deployment

`pages.yml` triggers on pushes touching `site/**`, uses the official Pages
actions, and needs no mechanical change. It is listed in this spec only because
the request named it; no change to it is planned unless verification shows
otherwise.

One asset check worth recording: `og:image` points at
`raw.githubusercontent.com/.../main/1.png`, which exists at the repo root, so
social previews are not broken today. It is noted only because a rename of that
file would silently break them.

## Success criteria

1. All 286 command paths execute in isolation with a recorded outcome, and the
   `NETWORK` count is published in the test output.
2. `CLOUDMESH_DIR` isolation is verified by a test that fails if any command
   writes outside its sandbox.
3. Every destructive or key-rotating command has a deep effect assertion, and
   the deep-coverage **ratio** tracks handler size, enforced as a CI floor.
4. `bandit`, `pip-audit`, and `gitleaks` run in CI with zero unexplained
   findings.
5. No argument vector produces an uncaught traceback.
6. No existing test is deleted.
7. The site reflects 3.5.1 and its command reference passes the same parser check
   the docs do.
8. Every new animation on the site is neutralised by the existing
   `prefers-reduced-motion` block, and no content is visible only because an
   animation ran.

## Risks

| Risk | Mitigation |
| --- | --- |
| Layer 1 is too shallow to catch anything | Layer 2 exists because Layer 1 is shallow; report how many real bugs it found on its first run |
| `CLOUDMESH_DIR` silently relocates a user's data | User-facing with a `doctor` row, a README section, and tests for unset/honoured/invalid |
| The suite gets slow | Per-command timeouts rather than more workers: the `smoke_cli.py` work showed parallelism does not help when the cost is process startup (520s sequential became 528s with eight workers) |
| `NETWORK` becomes a dumping ground | Each entry needs a stated reason; the count is reported |
| Coverage ratio goes stale | It is derived from `handler_lines` in the manifest, and CI fails when the ratio drops below its floor |

## Decisions taken in review

1. `CLOUDMESH_DIR` is documented and user-facing, with a doctor row, README, and
   CONTRIBUTING note â€” not a test-only hook.
2. Layer 2 depth is derived from handler size and PR complexity, enforced as a
   coverage ratio that moves with the codebase, with every destructive command
   required to be deep-tested regardless of size.
3. The website is developed in place â€” `site/` and `.github/workflows/pages.yml`
   â€” and tracked in this same stream rather than split into a separate PR. The
   goal is more depth and more motion: a verified command reference, per-command
   detail grouped by area, and scroll-triggered reveals and entrance motion that
   remain fully disabled under `prefers-reduced-motion`.
