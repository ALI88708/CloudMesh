# CloudMesh 3.5.1 â€” Behavioural Verification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make CloudMesh's CI catch real defects by executing all 286 command paths in isolation and asserting observable effects, so regressions fail a test instead of reaching a release.

**Architecture:** A `CLOUDMESH_DIR` environment override gives every command an isolated base directory, which is what makes executing destructive commands safe. A declarative manifest classifies each of the 286 paths by safety and records handler size; a runner executes them all isolated (Layer 1) and a hand-written suite asserts real effects for the risky ones (Layer 2). Coverage depth is enforced as a ratio rather than a count, so it tracks the codebase instead of going stale.

**Tech Stack:** Python 3.10â€“3.13, pytest with `pytest-timeout`, `rich` tables, subprocess, GitHub Actions (Linux + Windows), bandit, pip-audit, gitleaks, Hypothesis, `pytest.ini` (`timeout = 10`).

**Spec:** `docs/superpowers/specs/2026-10-10-cloudmesh-3.5.1-behavioural-verification-design.md`

## Global Constraints

- Python floor 3.10. Test on 3.10, 3.11, 3.12, 3.13 on both ubuntu-latest and windows-latest.
- `pytest.ini` sets `timeout = 10` per test. Any test spawning a subprocess must carry `@pytest.mark.timeout(N)` with `N > 10`.
- No existing test may be deleted. The 63 textual assertions stay.
- The batch file must remain CRLF (594 CRLF, 0 bare LF today). Shell scripts must remain LF.
- Parser introspection in tests must spy on `argparse.ArgumentParser.parse_args` and abort before dispatch. Never execute a command to learn the surface: `cm panic` rotates keys, `cm storage restore` overwrites the database.
- Every command path gets exactly one manifest entry. No entry may be `NETWORK` without a stated reason.
- Layer 2 depth is enforced as a coverage ratio, not an absolute count.
- Commits are pushed and merged manually by the maintainer. Never merge while CodeRabbit is pending.
- **The release is 3.5.1.** New features, so a minor version.

## Stability Contract

This release targets enterprises and must be safe to run for months without
updating. Four requirements, each with a task that proves it:

| # | Requirement | Proved by |
| --- | --- | --- |
| 1 | **Nothing that works in 3.5.0 breaks.** Zero-regression is the bar. Every bug the harness surfaces is fixed before it ships, not deferred. | Task 13 |
| 2 | **No new failures.** A command that works must keep working, at the same speed, with the same output. | Task 13 |
| 3 | **Identical results.** The same invocation must produce the same exit code and the same output as 3.5.0. Any difference is a regression by definition. | Task 13 |
| 4 | **No data loss, ever.** No file, no key, no database â€” not even under the destructive commands. | Task 14 |

Requirement 3 is the strict one, and it has a consequence worth stating plainly:
`CLOUDMESH_DIR` changes where storage lives, and the harness changes what the
default path is during tests. Neither may alter what a command returns for a
user who has not set the variable. Task 13 captures 3.5.0's behaviour first, then
compares, so a behavioural drift is caught rather than argued about.

The ordering of the plan follows from this. Tasks 1â€“7 build the harness, but a
harness that changes behaviour is worse than no harness, so Task 13 runs
against every task above it and blocks the release on any difference.

## Review Focus

Inputs the spec implies but no task's tests naturally exercise, most likely to bite first:

1. **`CLOUDMESH_DIR` set to a non-existent nested path** â€” must be created, not crash on first write. A reasonable person expects the variable to work the first time they set it.
2. **`CLOUDMESH_DIR` set to a path that cannot be created** (permission denied, or a file exists at that path) â€” must fail with a clear message, not a bare traceback.
3. **A command that reads state before writing it** â€” must see the isolated state, never a developer's real `cloudmesh.db`. This is the failure that silently corrupts a real install.
4. **Concurrent harness runs** â€” two invocations in the same checkout must not collide on `cloudmesh.db` or `.secret.key`.
5. **`cm uninstall` in isolation** â€” must remove only the sandbox tree, never the developer's install directory. Highest-consequence wrong-path bug in the whole harness.
6. **Windows path handling** â€” `CLOUDMESH_DIR` with backslashes, spaces, or a trailing separator must normalise identically to the POSIX case.

Each of these is pinned by a test in the task that owns the code.

```python
"""One entry per command path: how safe it is to run, and how deeply it is tested.

Pure data plus three helpers that read the real parser. Nothing here executes a
command: `cm panic` rotates every key and `cm storage restore` overwrites the
database, so the surface is derived by spying on `parse_args` and aborting
before dispatch.
"""

from __future__ import annotations

import argparse
import io
import re
import sys
from contextlib import redirect_stderr, redirect_stdout
from enum import Enum
from pathlib import Path
from typing import NamedTuple

_ROOT = Path(__file__).resolve().parent.parent
if str(_ROOT) not in sys.path:
    sys.path.insert(0, str(_ROOT))

_CAPTURED = "__captured__"


class Safety(Enum):
    SAFE = "safe"
    ISOLATED = "isolated"
    DESTRUCTIVE = "destructive"
    NETWORK = "network"


class CommandEntry(NamedTuple):
    path: tuple[str, ...]
    safety: Safety
    handler_lines: int = 0
    reason: str | None = None
    assertions: tuple[str, ...] = ()


def load_parser() -> argparse.ArgumentParser:
    import main as cloudmesh_main

    captured: dict = {}
    real = argparse.ArgumentParser.parse_args

    def spy(self, args=None, namespace=None):
        captured["parser"] = self
        raise SystemExit(_CAPTURED)

    argparse.ArgumentParser.parse_args = spy
    saved = sys.argv
    sys.argv = ["cloudmesh"]
    try:
        with redirect_stdout(io.StringIO()), redirect_stderr(io.StringIO()):
            cloudmesh_main.main()
    except SystemExit as exc:
        if exc.code != _CAPTURED:
            raise
    finally:
        argparse.ArgumentParser.parse_args = real
        sys.argv = saved
    return captured["parser"]


def _subparsers(node) -> dict:
    for action in node._actions:
        if isinstance(action, argparse._SubParsersAction):
            return action.choices
    return {}


def parser_paths() -> set[tuple[str, ...]]:
    top = _subparsers(load_parser())
    found, queue, seen = set(), [[n] for n in top], set()
    while queue:
        path = queue.pop()
        if tuple(path) in seen:
            continue
        seen.add(tuple(path))
        found.add(tuple(path))
        node = top[path[0]]
        for word in path[1:]:
            node = _subparsers(node).get(word)
            if node is None:
                break
        else:
            for child in _subparsers(node):
                queue.append([*path, child])
    return found


def handler_line_counts() -> dict[str, int]:
    """Line count of each `cmd_*` function, read from the source.

    Size is the proxy for branch count: a 200-line handler has more ways to be
    wrong than a 6-line wrapper, which is how Layer 2 depth is derived rather
    than guessed.
    """
    source = (_ROOT / "main.py").read_text(encoding="utf-8")
    counts: dict[str, int] = {}
    lines = source.splitlines()
    for index, line in enumerate(lines):
        match = re.match(r"def (cmd_\w+)\(", line)
        if not match:
            continue
        depth, end = 0, index
        for offset in range(index, len(lines)):
            depth += lines[offset].count("(") - lines[offset].count(")")
            end = offset
            if offset > index and depth <= 0:
                break
        counts[match.group(1)[4:]] = end - index + 1
    return counts


def sandbox_root(base: Path) -> Path:
    """Create and return the per-run sandbox at `base/<run>/{data,home}`.

    Every run gets its own tree so two runs in one checkout cannot collide on
    `cloudmesh.db` or `.secret.key`.
    """
    root = Path(base)
    for name in ("data", "home"):
        (root / name).mkdir(parents=True, exist_ok=True)
    return root
```

```python
"""Run every command in its own sandbox and record what happened.

Each run gets a fresh `HOME`, `USERPROFILE`, and `CLOUDMESH_DIR`, plus the real
package directory's mtimes captured beforehand. A command that writes anywhere
else is reported rather than allowed to corrupt a developer's install -- that is
the failure this whole harness exists to catch, and `cm panic` and
`cm uninstall` would otherwise do it silently.

Cost note, measured: each path costs roughly 1.8s of interpreter startup
importing cryptography and paramiko, which is CPU bound. `smoke_cli.py` measured
520s sequential and 528s with eight workers, so threads buy nothing here. The
budget goes into per-command timeouts, not concurrency.
"""

from __future__ import annotations

import os
import subprocess
import sys
from concurrent.futures import ThreadPoolExecutor
from pathlib import Path
from typing import NamedTuple

from cloudmesh.tests.command_manifest import COMMANDS, Safety, parser_paths

_PACKAGE_DIR = Path(__file__).resolve().parent.parent
_CAPTURE_PATHS = ("cloudmesh.db", ".secret.key", "config.json", "cloudmesh.json")
_PER_COMMAND_TIMEOUT = 60


class Outcome(NamedTuple):
    path: tuple[str, ...]
    safety: Safety
    returncode: int
    stdout: str
    stderr: str
    outside_sandbox: tuple[str, ...]
    skipped: bool


def _package_fingerprint() -> dict[str, float]:
    marks = {}
    for name in _CAPTURE_PATHS:
        target = _PACKAGE_DIR / name
        marks[name] = target.stat().st_mtime if target.exists() else -1.0
    return marks


def _written_outside(sandbox: Path, before: dict[str, float]) -> tuple[str, ...]:
    offenders = []
    for name, stamp in before.items():
        target = _PACKAGE_DIR / name
        now = target.stat().st_mtime if target.exists() else -1.0
        if now != stamp:
            offenders.append(f"{_PACKAGE_DIR / name}")
    return tuple(offenders)


def run_isolated(path: tuple[str, ...], sandbox: Path) -> Outcome:
    entry = COMMANDS[path]
    if entry.safety is Safety.NETWORK:
        return Outcome(path, entry.safety, 0, "", "", (), True)

    home = sandbox / "home"
    home.mkdir(parents=True, exist_ok=True)
    env = dict(os.environ)
    env.update({
        "HOME": str(home),
        "USERPROFILE": str(home),
        "CLOUDMESH_DIR": str(sandbox / "data"),
        "PYTHONWARNINGS": "ignore",
        "COLUMNS": "200",
    })
    before = _package_fingerprint()
    try:
        proc = subprocess.run(
            [sys.executable, str(_PACKAGE_DIR / "main.py"), *path],
            capture_output=True, text=True, timeout=_PER_COMMAND_TIMEOUT,
            env=env, cwd=str(_PACKAGE_DIR),
        )
        code, out, err = proc.returncode, proc.stdout or "", proc.stderr or ""
    except subprocess.TimeoutExpired:
        code, out, err = -1, "", f"timed out after {_PER_COMMAND_TIMEOUT}s"
    return Outcome(path, entry.safety, code, out, err, _written_outside(sandbox, before), False)


def all_outcomes(jobs: int = 4) -> list[Outcome]:
    import tempfile

    results: list[Outcome] = []
    paths = sorted(COMMANDS)
    with tempfile.TemporaryDirectory(prefix="cm-behaviour-") as root:
        sandboxes = [Path(root) / f"run{index}" for index in range(len(paths))]
        for box in sandboxes:
            box.mkdir(parents=True, exist_ok=True)

        def _one(item):
            path, box = item
            return run_isolated(path, box)

        with ThreadPoolExecutor(max_workers=max(1, jobs)) as pool:
            results = list(pool.map(_one, zip(paths, sandboxes)))
    return results


def escape_paths() -> list[Outcome]:
    return [o for o in all_outcomes() if o.outside_sandbox]


def coverage_ratio() -> tuple[float, int, int]:
    total = len(COMMANDS)
    deep = sum(1 for entry in COMMANDS.values() if entry.assertions)
    return (deep / total if total else 0.0), deep, total
```

```python
command's parser without enumerating commands by hand, and an uncaught

        raise SystemExit(_CAPTURED)

    saved = sys.argv
```

```python
def _cases():
    found = {}
    for block in re.findall(r"```[a-z]*\n(.*?)```", SITE.read_text(encoding="utf-8"), re.S):
        for raw in block.splitlines():
            line = raw.strip().lstrip("$ ").strip()
            if not re.match(r"^(cm|cloudmesh)\s+", line):
                continue
            line = re.split(r"\s+#", line)[0].rstrip("\\").strip()
            try:
                words = shlex.split(line, posix=True)[1:]
            except ValueError:
                words = line.split()[1:]
            for stop in (">>", ">", "<", "2>&1"):
                if stop in words:
                    words = words[: words.index(stop)]
                    break
            commands, index = [], 0
            while index < len(words):
                word = words[index]
                if word.startswith("-") or "/" in word or _PLACEHOLDER.match(word):
                    break
                commands.append(word)
                index += 1
                if len(commands) >= 2 and index < len(words) and words[index].startswith("-"):
                    break
            if commands:
                found.setdefault(
                    (tuple(commands), tuple(words[index:])), (commands, words[index:], line)
                )
    return list(found.values())

    assert len(_cases()) >= 5, "extractor found too few site examples"
```

## Execution Order

**Isolation first, then baseline.** An earlier draft of this plan put the
baseline capture first, before anything landed. That was wrong: capturing
behaviour means *running* every command, and running them unsandboxed is the
exact hazard `CLOUDMESH_DIR` exists to remove. A baseline taken that way would
have rotated real keys on the machine that took it.

So the harness is built first, and the baseline is captured afterwards by
pointing that harness at a 3.5.0 worktree. Same comparison, taken safely.

Sequence:

1. Tasks 1, 2, 3, 4, 5 — the sandbox and the harness, in order.
2. **Baseline capture** — run the harness from Task 5 inside a 3.5.0 worktree to
   produce `baseline_3_5_0.json`.
3. Tasks 6, 7 — deep assertions and the coverage floor.
4. Task 14 — the data-loss gate, then fix what it finds.
5. Task 13 — the regression gate, and triage every difference.
6. Tasks 8 and 11 in parallel — security scanning and the site, independent.
7. Task 9 — fuzzing, independent.
8. Task 12 — cut 3.5.1, last, so the changelog describes what actually landed.

Task 14 before Task 13 matters: data loss is the requirement that can hurt
someone's production system, so it is fixed and verified before the release gate
is switched on.
