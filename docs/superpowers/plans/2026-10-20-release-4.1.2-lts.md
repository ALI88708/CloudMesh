# CloudMesh 4.1.2 LTS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship CloudMesh `4.1.2` as the first published LTS: one `v4.1.2` tag, Python 3.11+, a GitHub-only update channel, API and ledger hardening, and parallel verification.

**Architecture:** Work on `release/4.1.2`, cut from `audit/4.0.1-stability`. Treat `3.4.0` as the published baseline and `4.0.0` as an internal changelog checkpoint. Keep the API loopback-only. Add one small `core/releases.py` for verified GitHub-release updates, a checkpoint to the command ledger, and targeted security tests around the existing API, database, and node modules.

**Tech Stack:** Python 3.11-3.13, stdlib (`urllib`, `hashlib`, `http.server`, `sqlite3`), pytest, rich, paramiko, cryptography. No new runtime dependency; `cyclonedx-bom` is CI-only.

**Spec:** `docs/superpowers/specs/2026-10-20-release-4.1.2-lts-design.md`

## Global Constraints

- Python floor is `>=3.11`; CI matrix is 3.11, 3.12, 3.13.
- No new mandatory runtime dependency.
- The REST API binds to `127.0.0.1` only; no external-bind flag.
- `/api/exec` is disabled by default; enabling it requires `--enable-exec`.
- The PyPI name `cloudmesh` is a different project. No code or install command may use it.
- All release downloads are verified against `SHA256SUMS`; failure is closed.
- TDD: failing test first, smallest change to green, then refactor.
- All new tests must pass on Windows without SSH, a node, or a BSD host.
- Remote values continue to pass through `shlex.quote`.
- Commit after every task with a conventional message.
- Test command: `python -m pytest cloudmesh/tests -q` from the repo root, or `python main.py test --suite` from `cloudmesh`.

## Review Focus

1. **`cm update --pip` under a hostile or broken GitHub response** — a missing `SHA256SUMS`, checksum mismatch, or 404 must stop before pip runs and must never fall back to PyPI.
2. **`cm api` defaults** — `/api/exec` returns 403 even with a valid key, and unauthenticated failures never append to `command_log.json`.
3. **`cm cmdlog --verify` after more than 500 commands** — the trimmed chain is valid, and editing the retained first entry or the checkpoint is still detected.
4. **A real 3.4.0 install** — JSON config, encrypted config, and plaintext profiles migrate to 4.1.2; rollback by reinstall plus config import works.
5. **Python 3.10** — installation is refused by `Requires-Python`, and no supported surface still advertises 3.10.

  6. call `_pip_install(str(wheel))`;
  7. return `f"Updated to CloudMesh {version}"`.

`CommandLog`:

- `_save()`:
  - overflow = `len(entries) - max_entries`;

  - return `valid=False` at the first mismatch, including a checkpoint/first-entry mismatch.
- `clear()` deletes the checkpoint and writes an empty log.
